## 1. 產品概述

內部 Web 系統，供員工申報以私人車輛執行公務所產生的三類補助，並由管理員維護帳號、全域補助參數、代操作與稽核：

1. **差旅補助**（油資 + ETC，依多段行程里程計算；油資每公里單價由「每公升油價 ÷ 員工車輛油耗」推導並取整）
2. **保養費用分攤**（依保養區間內公務里程比例分攤保養費）
3. **年度折舊補貼**（依年度公務里程與折舊每公里單價計算）

系統以「後端為計算唯一權威、已完成申請不可變、完成時保存計算快照、參數依日期版本化且不重疊」為核心設計骨幹。UI 與報表語言為 zh-TW。

技術棧（人類已確認，不得偏離）：

- 前端：React 18 + TypeScript + Vite（nginx 容器）
- 後端：Node.js + Fastify + Prisma + TypeScript（node 容器）
- 資料庫：PostgreSQL 16（獨立容器／受管服務）
- PDF：Playwright (Chromium) 渲染列印版 HTML（列印版與正式 PDF 同一份 HTML 版型）
- 測試：Vitest（unit/integration）+ Playwright（E2E）
- 部署：Zeabur 優先；本機 Docker Compose；環境差異一律走環境變數
- 認證：Cookie Session（HttpOnly / SameSite；正式環境 Secure）
- 儲存：storage 抽象層 + env 指定路徑之持久化 volume（MVP 不做 S3）

## 5. Phase 拆分（垂直切片）

拆分原則：

- 每個 Phase 是**可獨立驗收的垂直切片**：Phase 結束時人類可實際操作某個完整流程（登入、建立並完成一筆差旅、產生 PDF…）。不採「先全部 DB、再全部後端、最後 UI」的水平拆法。
- UI 驗收採兩道 Gate：**Mock Gate**（純前端以 mock 資料驗收互動與版面）與**整合 Gate**（前後端 + DB 串接後的端到端驗收）。含使用者可見 UI 的 Phase 皆觸發兩道 Gate；純基礎設施/後端 Phase 只觸發整合 Gate。
- High 風險判準（依 CLAUDE.md）：認證、授權、密碼、附件權限、不可逆操作（完成鎖定、作廢、參數版本、快照、永久刪除）。
- Git：一 Phase 一 branch 一 Draft PR（PHASE-001 之後）；PHASE-001 骨架與治理文件依 PROJECT_STATE 備註可直接進 main，惟仍建議走 branch + Draft PR 以建立流程慣例。
- **Human Gate** 欄位標示該 Phase 是否需人類事前批准（High 風險 Task）或事後驗收 Gate。

依賴總覽（關鍵縱向依賴）：

拆分理由（相對於 Task Packet 建議方向的調整說明）：

- 我將「補助參數維護」拆為獨立 **PHASE-003a** 並與附件基礎（PHASE-003）並列於差旅之前，因為 BE-US-09（套用差旅參數）、BE-US-19（參數版本不重疊）是差旅完成的硬前置；若參數維護排在差旅之後，PHASE-004 將無法達成「完成一筆差旅」的垂直驗收。此為對建議順序的必要調整，理由為縱向依賴。
- 「統計（區間里程）」PHASE-005 排在差旅之後、保養/折舊之前，因為保養（BE-US-11）與折舊（BE-US-15）的公務里程統計都複用區間里程引擎（BE-US-30）。先固化統計核心可避免保養/折舊重複實作與規格漂移。
- 保養（PHASE-006）與折舊（PHASE-007）彼此無強依賴，理論上可並行；但兩者都依賴 PHASE-004 已完成差旅與 PHASE-005 統計。文件以序號呈現，實作可視資源並行。
- 附件生命週期的「暫存清理排程」（BE-US-25 的 24 小時清理）歸入 PHASE-011 硬化，因其屬維運排程性質；附件的暫存→關聯→鎖定核心在 PHASE-003/004 完成。

- **目標**：建立可啟動的三容器骨架（nginx 前端 / node 後端 / PostgreSQL），前端可打到後端健康檢查，後端可連 DB；建立 CI（build/lint/test）、環境變數約定與結構化錯誤協定基礎。人類可在本機 `docker compose` 啟動並看到前端呼叫後端 `/health` 回傳正常。
- **Out of Scope**：任何業務功能、認證、資料表業務欄位（僅需 migration 機制與最小 health 檢查所需）。
- **對應 US**：NFR-US-01, 02, 03, 04, 05, 06, 15, 16（部分：錯誤協定與健康檢查骨架）。
- **Acceptance Criteria 摘要**：Compose 起三服務；前端連後端、後端連 DB；`/health` 正常/異常可回報；無寫死 secrets，全走 env；CI 綠燈；錯誤回應格式統一（可辨識欄位與原因，不外洩堆疊/DB 結構）。
- **UI 驗收**：整合 Gate（骨架端到端啟動）；Mock Gate 不觸發（尚無業務 UI）。
- **涉及層**：FE / BE / DB / 基礎設施。
- **Risk Level**：Medium（無 High Task；但錯誤協定與 env 約定影響全案）。
- **Human Gate**：事後整合驗收（啟動與 CI）。
- **初始 Task Graph 概要**：
  - T1 建立 monorepo/專案結構與 lint/format 設定
  - T2 後端最小 Fastify + `/health` + Prisma 連線（依 T1）
  - T3 前端最小 React+Vite + 呼叫 `/health`（依 T1）
  - T4 三容器 Dockerfile 雛形 + Docker Compose + env 範本（依 T2, T3）
  - T5 CI pipeline（build/lint/test）（依 T1..T4）
  - T6 結構化錯誤回應中介與慣例（依 T2）
- **High 風險 Task**：無。
- **Rollback 概要**：純新增檔案；回滾即刪除骨架分支/還原至 base commit，無資料遷移風險。

### PHASE-002 — 認證與帳號管理

- **目標**：完整登入/登出、Cookie Session、首次登入強制改密、自行改密；管理員使用者清單、新增、啟用/停用、重設密碼、條件式刪除；授權骨架（角色判斷 + 一般使用者資料隔離的中介層）與稽核寫入基礎。Phase 結束人類可：以管理員建帳號→使用者臨時密碼登入→強制改密→再登入→改密；管理員停用後該使用者無法登入且既有 session 失效。
- **Out of Scope**：任何補助申請資料（差旅/保養/折舊）；AD-US-04 刪除守門在「已有申請資料」的情境需待有申請後（PHASE-004+）才能完整回歸（本 Phase 先實作「無歷史即可刪、有歷史則拒絕」的判斷點，以帳號/session 為歷史來源）。
- **對應 US**：FE-US-01, 02, 03；AD-US-01, 02, 03, 04, 05；BE-US-01, 04；BE-US-02（授權骨架，申請資料情境於 004 補齊）；NFR-US-08, 09, 11（Cookie 安全屬性）。

- **涉及層**：FE / BE / DB。
- **Risk Level**：High。
- **Human Gate**：事前批准（High：認證/授權/密碼）+ Mock Gate + 整合 Gate。
- **初始 Task Graph 概要**：
  - T1 使用者與 Session 概念資料模型 + migration（依 001）

  - T5 認證中介層（受保護請求驗證、停用即失效）（依 T3）— **High**

  - T7 首次登入強制改密流程（依 T3）— **High**

  - T11 前端登入/改密/使用者管理頁（依 T3, T9）

### PHASE-003 — 附件基礎（storage 抽象、上傳、驗證、生命週期、授權存取）

- **目標**：建立與申請類型無關的附件通用能力：storage 抽象層 + env 持久化 volume；上傳（格式/大小驗證、實際內容檢測防偽副檔名）、暫存標示、預覽縮圖、授權存取端點、暫存→草稿關聯→刪除解除關聯的生命週期核心與引用保護。Phase 結束人類可（透過測試頁或最小宿主表單）上傳合法圖片、看到暫存與預覽、被拒絕非法格式/超大檔、非授權者無法存取他人附件。
- **Out of Scope**：各申請類型的附件數量上限套用與「完成時鎖定」的正式落地（於 PHASE-004/006/007）；24 小時暫存清理排程（於 PHASE-011）。本 Phase 提供限制引擎與生命週期 API，具體上限值由各申請 Phase 套用。
- **對應 US**：BE-US-23, 24（限制引擎）, 25（暫存/關聯/引用保護核心）；NFR-US-07, 10；FE-US-21（附件通用互動，差旅情境於 004 驗收）。
- **Acceptance Criteria 摘要**：接受 JPEG/PNG/WebP 且驗真實內容；改副檔名偽裝被拒；單檔 >10MB 拒絕；PDF/其他格式拒絕；上傳後標示暫存；授權通過才回傳檔案，未登入或非擁有者不得取得內容；草稿刪附件解除關聯；被引用的附件不得被清理。
- **UI 驗收**：整合 Gate（含最小上傳/預覽宿主）；Mock Gate（上傳元件互動與預覽）。
- **涉及層**：FE（上傳元件）/ BE / storage / DB。
- **Risk Level**：High（附件權限）。
- **Human Gate**：事前批准（High：附件權限）+ Mock Gate + 整合 Gate。
- **初始 Task Graph 概要**：
  - T1 Attachment 概念資料模型（暫存/關聯欄位、引用來源）+ migration（依 002）
  - T2 storage 抽象層 + env 路徑/持久化 volume（依 001）
  - T3 上傳與驗證（格式/大小/實際內容檢測）（依 T1, T2）— **High**
  - T4 附件數量限制引擎（可配置上限）（依 T1）
  - T5 授權存取端點（擁有權驗證後才回傳）（依 T1, 002 授權中介）— **High**
  - T6 生命週期：暫存→關聯→解除關聯 + 引用保護（依 T1）— **High**
  - T7 前端上傳/預覽/刪除元件（依 T3, T5）
- **High 風險 Task**：T3, T5, T6。
- **Rollback 概要**：新增資料表、端點與 volume 掛載；回滾須確保已寫入 volume 的暫存檔清理策略不誤刪被引用檔案。開發階段為合成檔案，回滾風險可控。
