## 0. 人類裁定原文（引用出處：`PROJECT_STATE.md` L8）

1. 油資參數由「每公里單價」改為「**每公升油價，按油種維護**（92/95/98/柴油），生效日期版本化」
2. 新增「員工車輛油耗（km/L）＋油種」屬性，**僅管理員可維護**（與員工人工核對後 key in），生效日期版本化、依出差日期取值
3. 每公里油資單價＝油價÷油耗，**取整數**（一般四捨五入）
4. 員工未建油耗資料時**擋油資申請**並提示洽管理員，不設 fallback
5. 油耗維護留依據備註與異動紀錄（稽核）

## 1. AD-US-11 修訂對照

### 1.1 現行原文（`userstory.md` L1011–L1031，逐字引用）

```
## AD-US-11 維護油資補助參數

作為管理員，我希望建立有生效日期的油資每公里補助參數，以便系統依出差日期套用正確單價。

### 驗收條件

* Given 管理員輸入大於或等於 0 的油資單價及生效日期
  When 建立參數版本
  Then 系統應保存新版本。

* Given 新版本有效期間與既有版本重疊
  When 管理員提交
  Then 系統應拒絕並指出衝突。

* Given 新版本在未來日期生效
  When 管理員建立
  Then 舊版本在新版本生效前仍應有效。

* Given 歷史差旅已完成
  When 管理員新增新版本
  Then 歷史申請金額不得改變。
```

### 1.2 修訂後全文（提案）

```
## AD-US-11 維護油價參數（按油種）

作為管理員，我希望依油種建立有生效日期的每公升油價參數，以便系統依出差日期及員工車輛油種取得正確油價。

### 驗收條件

* Given 管理員選擇油種並輸入大於或等於 0 的每公升油價及生效日期
  When 建立參數版本
  Then 系統應保存該油種的新版本。

* Given 新版本有效期間與同一油種的既有版本重疊
  When 管理員提交
  Then 系統應拒絕並指出衝突。

* Given 新版本有效期間與其他油種的既有版本重疊
  When 管理員提交
  Then 系統應允許建立，各油種的版本有效期間互不干涉。

* Given 新版本在未來日期生效
  When 管理員建立
  Then 同一油種的舊版本在新版本生效前仍應有效。

* Given 歷史差旅已完成
  When 管理員新增新版本
  Then 歷史申請金額不得改變。
```

### 2.1 AD-US-15 維護員工車輛油耗與油種（新增，置於 AD-US-14 之後）

```
## AD-US-15 維護員工車輛油耗與油種

作為管理員，我希望為每位使用者建立有生效日期的車輛油種與油耗資料，以便系統依出差日期推導該使用者的油資每公里單價。

### 驗收條件

* Given 管理員選擇一位使用者，輸入油種、大於 0 的油耗、生效日期及依據備註
  When 建立油耗資料版本
  Then 系統應保存該使用者的新版本。

* Given 油耗小於或等於 0
  When 管理員提交
  Then 系統應拒絕並指出錯誤欄位。

* Given 依據備註未填寫
  When 管理員提交
  Then 系統應拒絕並要求填寫核對依據。

* Given 新版本有效期間與同一使用者的既有版本重疊
  When 管理員提交
  Then 系統應拒絕並指出衝突。

* Given 新版本有效期間與其他使用者的版本重疊
  When 管理員提交
  Then 系統應允許建立，各使用者的版本有效期間互不干涉。

* Given 新版本在未來日期生效
  When 管理員建立
  Then 該使用者的舊版本在新版本生效前仍應有效。

* Given 該使用者已有已完成差旅
  When 管理員新增新版本
  Then 歷史申請金額不得改變。

* Given 一般使用者嘗試建立、修改或刪除任何油耗資料，包含自己的資料
  When 系統驗證權限
  Then 應拒絕操作。

* Given 管理員建立或修改油耗資料成功
  When 系統保存
  Then 應產生稽核紀錄，包含操作者、資料對象使用者、時間、異動前後的油種與油耗摘要及依據備註。

* Given 管理員查看某位使用者的油耗資料
  When 顯示資料
  Then 應可看到目前生效版本、未來生效版本及歷史版本，並可辨識各版本的生效日期與依據備註。
```

### 2.2 FE-US-28 檢視個人車輛油耗資料（新增，置於 FE-US-27 之後）

```
## FE-US-28 檢視個人車輛油耗資料

作為一般使用者，我希望查看管理員為我登錄的車輛油種與油耗，以便確認油資補助的計算基礎正確。

### 驗收條件

* Given 使用者已登入且目前有生效中的油耗資料
  When 開啟個人資料檢視
  Then 系統應顯示目前生效的油種、油耗及該版本生效日期。

* Given 使用者尚未有任何油耗資料
  When 開啟個人資料檢視
  Then 系統應顯示尚未建立的空白狀態，並提示聯絡管理員建立。

* Given 使用者檢視自己的油耗資料
  When 顯示畫面
  Then 系統不得提供新增、修改或刪除入口。

* Given 使用者發現油耗資料與實際車輛不符
  When 查看畫面說明
  Then 系統應提示由管理員核對後更新。
```

### 2.3 BE-US-32 解析油資每公里單價（新增，置於 BE-US-31 之後）

```
## BE-US-32 解析油資每公里單價

作為系統，我需要依出差日期解析申請擁有人的車輛油耗及其油種的每公升油價，以推導油資每公里單價。

### 驗收條件

* Given 出差日期存在該擁有人有效的油耗版本，且該版本的油種在該日期存在有效的油價版本
  When 計算油資每公里單價
  Then 應使用「每公升油價 ÷ 油耗」，並以一般四捨五入取為新臺幣整數。

* Given 油資每公里單價已取整
  When 計算行程段油資補助
  Then 應使用「總里程 × 取整後的油資每公里單價」。

* Given 申請擁有人在出差日期沒有有效油耗資料
  When 儲存草稿
  Then 系統應允許保存。

* Given 申請擁有人在出差日期沒有有效油耗資料
  When 嘗試完成差旅申請
  Then 系統應拒絕完成，並提示聯絡管理員建立油耗資料；不得以預設值、替代值或其他使用者的資料計算。

* Given 出差日期沒有該油種的有效油價版本
  When 嘗試完成差旅申請
  Then 系統應拒絕完成，並提示聯絡管理員設定參數。

* Given 管理員代替使用者操作差旅申請
  When 系統解析油耗與油價
  Then 應以申請擁有人的油耗資料為準，不得使用操作者的資料。

* Given 差旅申請已完成
  When 管理員後續修改油價參數或該使用者的油耗資料
  Then 歷史差旅的單價與金額不得改變。

* Given 前端提交自訂油資每公里單價、油價或油耗
  When 後端處理
  Then 不得直接採用前端提交的數值。
```

| **Q2** | `userstory.md` §七 已將「車輛主檔」列為不在範圍；新增之「使用者車輛油種＋油耗」屬性是否構成車輛主檔？ | **維持「車輛主檔」為 Out of Scope，並於該列加註**：僅納入油種與油耗兩項補助計算必要屬性，不含車牌、廠牌、車型、車籍等主檔欄位 | userstory §七、PRD §3 |

| **Q6** | 油耗資料的「依據備註」是否為必填？ | **必填**（裁定⑤要求留依據；選填等同可空白，稽核價值消失） | AD-US-15 第 3 條 AC |
| **Q7** | 數值精度與值域：每公升油價與油耗各允許幾位小數？油價是否維持「≥0」（容許 0）？ | **油價允許小數（沿用既有參數精度慣例）且維持 ≥0；油耗允許小數且必須 >0**（作為除數不得為 0）。實際小數位數屬 Phase Spec 層，此處僅定「油價 ≥0、油耗 >0」 | AD-US-11、AD-US-15、BE-US-32 |
| **Q8** | 計算快照是否須同時保存油種、每公升油價、油耗三項（而非只存推導後單價）？ | **須保存三項**（僅存單價則無法重現推導、無法對帳，違反 BE-US-18「歷史資料可以重現」之目的） | BE-US-18 |
| **Q9** | 單價取整為整數後，行程段金額是否仍依 BE-US-06 既有規則（油資＋ETC 先相加再一次四捨五入）？ | **是，維持既有規則不變**；取整只發生在單價推導與段金額兩處，不新增第三處取整 | BE-US-06、BE-US-32 |
| **Q10** | 每公升油價屬全域參數，一般使用者是否可經自己的差旅預覽推知？ | **可**，且不得以此作為安全前提（沿用 PHASE-004 D6 已批准之授權邊界，見 `PROJECT_STATE.md` L236） | FE-US-10、授權設計 |
