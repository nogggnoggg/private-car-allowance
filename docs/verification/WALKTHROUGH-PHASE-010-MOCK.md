## 這次要看什麼（30 秒版）

管理員多了一頁「稽核紀錄」：誰、什麼時候、對誰、做了什麼、**改前改後是什麼**。
**驗收核心只有一件事（AD-US-14③）：「改前改後」那一欄，不懂技術的人看不看得懂。**
其餘（篩選、翻頁、五態文案）為常規檢查。

## 前置（大總管於 Gate 前完成，您不用做）

- dev DB 已播種：至少各一筆——建立帳號、停用＋啟用、密碼重設、代建草稿、作廢（含中文原因）、參數版本（三型）、油耗版本（含異動前後）。
- 兩個測試帳號：管理員 `e2eadmin`、一般使用者一名（密碼由大總管當場提供，全合成）。

## Step-by-step

### A. 入口與權限（2 分鐘）

1. 以**管理員**登入 → 首頁管理員區塊應有「**稽核紀錄**」入口 → 點入。
2. 預期：列表載入，每列四要素——**操作時間**（台北時間，不是 `2026-08-09T06:00:00Z` 這種原始格式）／**操作者**（顯示名稱，不是一串 ID）／**操作類型**（中文，如「作廢申請」，不是 `APPLICATION_VOIDED`）／**受影響資料**。
3. 登出，改以**一般使用者**登入 → 首頁**不應**出現「稽核紀錄」入口；直接在網址列輸入 `/admin/audit-logs` → 應顯示無權限訊息、**看不到任何稽核內容**。

### B. 改前改後摘要——驗收核心（5 分鐘）

以管理員回到稽核頁，逐一找到下列事件並展開看「欄位／改前／改後」表格：

| 找哪筆 | 應該看到 | 不能看到 |
|---|---|---|
| 油耗資料異動 | 「異動前版本」「異動後版本」兩列（內容為油種/油耗數值），加「依據備註」一列 | `[object Object]`；欄位名顯示成「改前」和表頭撞名 |
| 作廢申請 | 「作廢原因」一列，中文原因**逐字**可讀 | 原因被截斷成看不懂、或顯示英文鍵名 `reason` |
| 密碼重設 | 只有「須變更密碼」一列，值為 true | **任何**看起來像密碼的東西 |
| 停用帳號 | 啟用狀態的變化（from/to） | 亂碼或空白 |
| 參數版本建立 | 參數類型與數值欄位（中文標籤） | — |

4. **總結判斷**：這張表拿給完全不懂系統的同事看，能不能說出「誰把什麼從 A 改成 B」？能＝過。

### C. 篩選與分頁（3 分鐘）

5. 用「操作類型」下拉選一類（如「作廢申請」）→ 列表收斂到只剩該類。
6. 設日期區間（起訖同一天，選有事件的那天）→ 該天事件在列；改成無事件的日期 → 顯示「查無稽核紀錄。」（注意：與完全沒資料時的「尚無任何稽核紀錄。」是兩句不同的話）。
7. 清掉篩選，翻到第 2 頁再套任一篩選 → 應自動回到第 1 頁。
8. 第 1 頁時「上一頁」應為灰色不可按；最末頁時「下一頁」灰色不可按。頁腳有「第 N 頁／共 M 筆」。

### D. 版面極端值（2 分鐘）

9. 找一筆**長中文作廢原因**的列 → 版面不應被撐爆或水平捲動。
10. 瀏覽器視窗縮到手機寬（約 375px）→ 列表仍可讀、無水平溢位。（正式 375px 驗證在 T8 E2E，此處目視即可。）

### E. 錯誤態（1 分鐘，可選）

11. 大總管當場停掉 backend-dev → 重新整理稽核頁 → 應顯示錯誤訊息＋「重試」鈕；重啟後按重試恢復。

## 這期不會做的事（先講清楚）

- 稽核資料的清理/保留期限、匯出——不在範圍（PHASE-011 之後再議）。

## 揭露事項（Gate 時請知悉）

1. 「操作類型」的**中文標籤字面**（如「作廢申請」「重設密碼」）為本期實作首次擬定，Spec 未逐字指定——若您對任一標籤用詞有意見，現在改成本最低。
2. 油耗異動的「異動前版本/異動後版本」內容顯示為 JSON 樣式字串（如 `{"fuelType":"GASOLINE_95",...}`）——這是 Gate 已裁定（D3=(c) 單一通用攤平）的已知代價；若您希望更進一步美化，屬新需求另議。
