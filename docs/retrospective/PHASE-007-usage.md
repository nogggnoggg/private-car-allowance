## 2. 型態驗證（對 005a/006 型態①~⑧逐項以本 Phase 數據覆核）

### ①「成本頂部＝可預測接線帶（排除事故）」——**驗證成立，頂部再收斂**

本 Phase 排序：T7 306k > T16 264k > SPEC-007 243k > T4 241k ≈ T9/T9b 審 223k ≈ 終審 218k > T9 214k。**零事故**（006 型⑧大戶零再現、005a 型⑤波及面大戶零再現）。頂部全數為可預測型態：接線大戶（T7——computed 接入橫跨 7 檔，130 tool uses）、E2E 環境迭代（T16）、Spec 全文。**T7 306k 貼近但未破拆分線 320k**——006 校準的接線型拆分線首次受實測壓力，判定：線位正確（T7 一輪清零、修復僅暖續派低增量，未拆是對的）；但 7 檔＋九項 FW 處置已是此線下的極限形狀，**再多一項義務即應拆**。

### ②「語意性 BLOCKED 重派、機械性續派」——**細化：新增「機械連動 BLOCKED→暖續派」分支，三案實證**

本 Phase 三次 BLOCKED（防呆第五、六、七次攔截）性質全為**機械連動／Packet 清單誤差**，非語意歧義：T1（表數寫死 2 行連動）、T9（T7 守門測試計數 3→4）、T11（AC-35 落點檔被 Packet 誤列 Forbidden，Spec §15 同漏）。三案處置一致：implementer 未私改、據實回報 → 大總管裁定後**暖續派同 agent**，增量 ~5k／低增量／低增量。**成本效益結論**：三次攔截之處置總成本 <~20k，換得零私改、零 Forbidden 越界、零污染——對照若任一案 implementer 私改（006 T9 事故稅 ~450-500k 之風險面），防呆條款（治理 2026-08-04.1 :710 常文）投報率延續 006 結論。005a「語意性 BLOCKED 開新 agent」規則本 Phase 無適用案例，維持。

### ③「Lite 帶輕/重雙檔」——**重大修正：暖續派使雙檔帶對「原 agent 存活」情境失效，新型態⑨成立**

006 帶（輕 50-100k／重 130-140k）之隱含前提是**冷派新 agent**（context 從零建立）。本 Phase 修復回合幾乎全走暖續派：有記錄 4 筆增量 **5k／11k／13k／14k**——其中 T6R、T9R2 依 006 定義屬「重 Lite」（2-3 finding 併修＋紅燈實證義務），冷派估 130-140k，暖續派實測 13-14k，**省約 90%**。見下「新型態⑨」。冷派 Lite 本 Phase 無有記錄數據點（T11R/T12R/T14R 等未記錄），006 雙檔帶對冷派情境**維持沿用、無新校準**。

### ④「reviewer 重驗證級 ~155-195k」——**驗證成立且帶寬上下皆展延：單 Task 重驗證 ~106-205k、合併重驗證／終審 ~215-225k**

12 筆全記錄。單 Task 重驗證（含搭車確認）：106-199k——下緣由純函式即審（T1/T2/T3：106-129k，Spec 附逐字 kill case 使重驗證便宜）拉出，較 006 帶下修；上緣 T4 190k／T7 審 199k。**合併重驗證**（2 Task）：T6/T6b 205k、T9/T9b 223k——006 無此數據，新檔。終審 218k（46 AC 機械化逐字核對＋12 mutant）。標準級合併複審（3 Task）153k 與 006 帶一致。**「全綠真缺陷」捕獲率——重驗證級的存在理由再獲強證**：本 Phase 全套測試綠燈下由 reviewer 重驗證抓出的真缺陷至少 6 件——T4 SF-1（M13 全套全綠存活、對帳子句零鑑別）、T7 審 SF-1（共用可變 missing 陣列，PROBE-7 全行程污染、2110 測試零偵測）、T9 審 S-1（tx 邊界零鑑別，M2/M3 移出交易全套零偵測）、T10 審 SF-1（C2 時間戳恆真格）、T11 審 SF-1（hook 用 tx 零鑑別）、終審 SF-2（createdAt tie-breaker 三 Phase 覆蓋缺口）。全數為 mutant 獨立重現／自寫探針所得，非重驗證抓不到；且全 Phase 僅 1 Must（純文件）——重驗證級即審把缺陷攔在 Should 級。

### ⑥「E2E 環境事實前置則成本正常化」——**部分回擺：T16 264k/128 證明『環境事實敏感』是雙向的**

### ⑦「機械性中斷 SendMessage 續行成本低」——**大幅擴張適用面，與③合流為型態⑨**

005a ⑦原限「API 斷線」；本 Phase 實證：凡**原 agent context 仍為有效資產**（BLOCKED 機械連動、即審後 R 輪修自己的產出），暖續派均為數量級優勢。006 ⑦的警語（角色錯亂 context 已污染者勿續推）維持——本 Phase 零角色錯亂，無反例。

### ⑧「角色錯亂＋巢狀派工」——**零再犯（連續第二個 Phase）**

禁止條款已為治理常文（2026-08-04.1 :710），本 Phase 20+ 次派工零再現。型態⑧轉入「已被條款壓平」狀態，與⑤⑥同列。

### 新型態⑨（本報告新立）：暖 context 續派之低增量修復

- **定義**：原 implementer agent 尚存活（同 session、context 未污染）時，將其產出之修復回合（BLOCKED 機械連動解除、即審 SF/AR 修復）以 SendMessage 續派原 agent，而非冷派新 Lite agent。
