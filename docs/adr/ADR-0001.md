# ADR-0001 — 部署目標：前端、後端、PostgreSQL 全部部署於 Zeabur

- 狀態：ACCEPTED（人類確認，2026-08-01）
- Governance-Version: 2026-08-01.1

## 背景

Project Execution Profile 原確認「Zeabur 優先」。使用者於 2026-08-01 進一步確認：正式環境的前端、後端與 PostgreSQL **三個服務都部署在 Zeabur**（PostgreSQL 使用 Zeabur 服務 + 持久化 volume，非外部受管資料庫）。

## 決定

1. 正式環境三服務均為 Zeabur 服務：nginx 前端、node 後端、PostgreSQL 16。
2. **同源策略**：瀏覽器只面對前端網域；nginx 以 `/api` 反向代理至後端（走 Zeabur 私有網路）。Cookie Session 因此維持同源（SameSite=Lax、HttpOnly、正式 Secure），不引入 CORS 與跨站 Cookie 複雜度。
3. 附件與正式 PDF 存於後端服務掛載的 Zeabur 持久化 volume，路徑由環境變數提供（與假設 A2 一致）。
4. PostgreSQL 資料存於 Zeabur volume；連線一律由 `DATABASE_URL` 等環境變數提供。
5. 備份約束：因 DB 與附件都在 Zeabur，NFR-US-12「備份不得只存於正式系統相同主機/磁碟」意味著備份必須**匯出至 Zeabur 之外**（具體機制於 PHASE-011 Spec 定案）。

## 替代方案

- 外部受管 PostgreSQL（如 Neon/Supabase）：降低備份負擔，但增加服務商數量與成本；使用者已選擇全 Zeabur。
- 前後端各自網域 + CORS + SameSite=None：可行但擴大攻擊面與複雜度，且與 Cookie Session 決策（A4）衝突較多，不採。

## 影響

- PHASE-002（Spec 前置）：Session/Cookie 設計以同源為前提。
- PHASE-003：storage 抽象層預設實作為「env 指定路徑之本機/volume 目錄」。
- PHASE-008：Playwright/Chromium 需打包進後端 image（注意 image 大小與 Zeabur 資源限制，Spec 時評估）。
- PHASE-011：部署細節、HTTPS（Zeabur 自帶憑證）、volume 掛載、備份匯出 Zeabur 之外的機制，均於該 Phase Spec 展開。
- 本機開發以 Docker Compose 模擬同構拓撲（nginx proxy /api → backend → postgres + volume）。

## Rollback

平台無關性由環境變數與 storage 抽象層保障（NFR-US-01..05/07）；搬離 Zeabur 時僅更換部署設定與環境變數，不改核心業務邏輯。
